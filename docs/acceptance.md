## 性能测量

`npm run benchmark` 使用 JSDOM 的 1,000 个段落（含内联代码），连续提取 5 次；模型服务为本地 SSE，末次输出延迟 20ms，测量第一次冷翻译和第二次缓存命中。结果如下：

| 指标                      | 本次结果                                      |
| ------------------------- | --------------------------------------------- |
| 提取 5 次                 | 260.45 / 61.28 / 55.97 / 53.48 / 55.57 ms     |
| 提取中位数                | 55.97 ms                                      |
| 冷翻译总耗时              | 45.54 ms                                      |
| Pi 报告模型耗时           | 35 ms                                         |
| 本地缓存路径              | 0.04 ms；模型调用仍为 1 次                    |
| 实际 MV3 布局/键盘 / 读屏 | 浅深色、宽窄布局与键盘 E2E 通过；读屏仍待验收 |

这些是特定本机的合成测量，不代表真实浏览器布局成本、互联网模型延迟或其他机器的性能。冷提取首次初始化成本单独保留，没有删掉较慢样本。

实际 Chromium MV3 合成压力：1,000 个可见段落首遍 876ms、63 个批次，100 次 SPA 替换后共 163 次请求；代码保持、停止清理通过。超大 viewport 使所有段落可见；此耗时包括本地模拟模型、排队与渲染，不是单独提取性能或互联网模型延迟。`npm run test:e2e -- tests/e2e-browser/stress.spec.ts` 可复现。

内嵌双语和轻量控件实现及限制见 [UI 设计](ui-design.md)，本机版本化产物流程见 [发布准备](release-readiness.md)。

实际 MV3 设置页导航反馈（点击至第二次 requestAnimationFrame）浅色 36.2 / 31.3 / 31.7ms，深色 35.2 / 30.5 / 32.4ms；只近似本地绘制就绪，排除模型与网络，不能替代 Discord 或读屏延迟。

真实公开 [LLVM Programmer’s Manual](https://llvm.org/docs/ProgrammersManual.html) 的普通文章布局检查已通过：27 处译文、6 次本地模拟请求，恢复后 99 个代码块、803 个链接和 29 个输入控件的数据完全一致，截图人工检查。复现：`LINGO_SOFA_PUBLIC_ACCEPTANCE=1 npm run test:e2e -- tests/e2e-browser/public-page.spec.ts`；此测试需要网络，默认跳过，不发送 API Key，不证明真实模型质量。更广的网站矩阵仍待验收。

## 体验中模型回显元数据修复（2026-10-14）

真实 Discord 体验发现模型可能在结果中回显输入 `targetLanguage`，或同时回显 `context`，严格结果校验因此拒绝译文。模型输出解析现在仅额外接受这两项已知元数据，并按输入边界校验类型和长度；对齐和恢复后仍只返回 `id/revision/text`，其他未知字段、错 ID、重复/缺项和损坏的保护标记继续拒绝。提示词明确禁止回显，缓存提示版本升至 translation-v2。

回归覆盖元数据丢弃、类型/长度错误、任意额外字段，以及模拟模型 → 实际 HTTP Bridge → 严格 Reply 校验。原客户端的两条已有失败翻译重试后显示正常译文；只重试用户已发起的翻译，不发布或删除用户消息。体验 Bridge 重启时保留原配对令牌及已有用量记录，不重置已消耗预算；服务继续运行供用户体验。

## 深色主题译文颜色修复（2026-10-14）

Discord 当前正文变量为 `--text-default`；只读取旧的 `--text-normal` 会使译文回退到容器默认颜色。插件现在优先读取当前主题的正文、背景和边框变量，再回退到旧版变量；译文段落显式继承正文颜色，取消透明度衰减。网页整段和选区译文也保持原文字色、不降低不透明度。

`discord-theme.spec.ts` 用真实 Chromium CSS 渲染检查当前/旧版变量的深浅主题切换；当前变量优先于故意设为黑色的旧变量，译文、标题、按钮、输入框的颜色和背景均跟随变化。内嵌网页 E2E 检查原文/译文颜色一致、主题切换不重复派发，原 Discord 已重新加载插件并配对，在深色主题下检查了实际浅色译文；未改变用户的频道自动模式设置，Bridge 保持运行。

## Discord Provider 配置简化（2026-10-14）

Vencord 配置页改为供应商/模型/API Key 单一面板，标准模型端点自动填充，自定义 OpenAI 兼容端点才显示地址输入。端口、语言和频道列表的宿主表单隐藏；所有频道均可手动翻译，自动模式保留频道内授权。桌面 native helper 自动读取本地短期连接描述文件，语言仍在悬浮入口，用量/草稿移到更多操作。

原 `/Applications/Discord.app` 的 LingoSofa 服务器已验证自动连接、现有四条消息的双语显示、深色 Provider 面板，以及 OpenAI 模型自动填充和缺少相应 Key 时禁用保存。未改变用户当前 DeepSeek 配置，未发送或删除消息。实际多供应商凭据不齐，OpenAI 等其他供应商的真实服务调用仍待用户提供对应凭据；目录与保存、来源/令牌拒绝、禁止跨供应商复用 Key、忙碌时拒绝修改、0600 持久化和描述文件失效均用回归测试覆盖。

`provider-settings.spec.ts` 渲染实际组件，检查多供应商模型联动、密码输入、保存失败/成功反馈与清空 Key、自定义地址、400px 单列且无横向溢出。现有主题测试继续覆盖深浅主题色；真机浅色主题仍待验证。连接描述文件不包含 Provider Key，Provider 返回接口也不返回 Key；配置作用于同一 Bridge 的所有连接端，保存保留账本与预算并清理旧会话/缓存。
