## 性能测量

`npm run benchmark` 使用 JSDOM 的 1,000 个段落（含内联代码），连续提取 5 次；模型服务为本地 SSE，末次输出延迟 20ms，测量第一次冷翻译和第二次缓存命中。结果如下：

| 指标                      | 本次结果                                      |
| ------------------------- | --------------------------------------------- |
| 提取 5 次                 | 260.45 / 61.28 / 55.97 / 53.48 / 55.57 ms     |
| 提取中位数                | 55.97 ms                                      |
| 冷翻译总耗时              | 45.54 ms                                      |
| Pi 报告模型耗时           | 35 ms                                         |
| 本地缓存路径              | 0.04 ms；模型调用仍为 1 次                    |
| 实际 MV3 布局/键盘 / 读屏 | 浅深色、宽窄布局与键盘 E2E 通过；读屏仍待验收 |

这些是特定本机的合成测量，不代表真实浏览器布局成本、互联网模型延迟或其他机器的性能。冷提取首次初始化成本单独保留，没有删掉较慢样本。

实际 Chromium MV3 合成压力：1,000 个可见段落首遍 876ms、63 个批次，100 次 SPA 替换后共 163 次请求；代码保持、停止清理通过。超大 viewport 使所有段落可见；此耗时包括本地模拟模型、排队与渲染，不是单独提取性能或互联网模型延迟。`npm run test:e2e -- tests/e2e-browser/stress.spec.ts` 可复现。

内嵌双语和轻量控件实现及限制见 [UI 设计](ui-design.md)，本机版本化产物流程见 [发布准备](release-readiness.md)。

实际 MV3 设置页导航反馈（点击至第二次 requestAnimationFrame）浅色 36.2 / 31.3 / 31.7ms，深色 35.2 / 30.5 / 32.4ms；只近似本地绘制就绪，排除模型与网络，不能替代 Discord 或读屏延迟。

真实公开 [LLVM Programmer’s Manual](https://llvm.org/docs/ProgrammersManual.html) 的普通文章布局检查已通过：27 处译文、6 次本地模拟请求，恢复后 99 个代码块、803 个链接和 29 个输入控件的数据完全一致，截图人工检查。复现：`LINGO_SOFA_PUBLIC_ACCEPTANCE=1 npm run test:e2e -- tests/e2e-browser/public-page.spec.ts`；此测试需要网络，默认跳过，不发送 API Key，不证明真实模型质量。更广的网站矩阵仍待验收。

## 体验中模型回显元数据修复（2026-10-14）

真实 Discord 体验发现模型可能在结果中回显输入 `targetLanguage`，或同时回显 `context`，严格结果校验因此拒绝译文。模型输出解析现在仅额外接受这两项已知元数据，并按输入边界校验类型和长度；对齐和恢复后仍只返回 `id/revision/text`，其他未知字段、错 ID、重复/缺项和损坏的保护标记继续拒绝。提示词明确禁止回显，缓存提示版本升至 translation-v2。

回归覆盖元数据丢弃、类型/长度错误、任意额外字段，以及模拟模型 → 实际 HTTP Bridge → 严格 Reply 校验。原客户端的两条已有失败翻译重试后显示正常译文；只重试用户已发起的翻译，不发布或删除用户消息。体验 Bridge 重启时保留原配对令牌及已有用量记录，不重置已消耗预算；服务继续运行供用户体验。

## 深色主题译文颜色修复（2026-10-14）

Discord 当前正文变量为 `--text-default`；只读取旧的 `--text-normal` 会使译文回退到容器默认颜色。插件现在优先读取当前主题的正文、背景和边框变量，再回退到旧版变量；译文段落显式继承正文颜色，取消透明度衰减。网页整段和选区译文也保持原文字色、不降低不透明度。

`discord-theme.spec.ts` 用真实 Chromium CSS 渲染检查当前/旧版变量的深浅主题切换；当前变量优先于故意设为黑色的旧变量，译文、标题、按钮、输入框的颜色和背景均跟随变化。内嵌网页 E2E 检查原文/译文颜色一致、主题切换不重复派发，原 Discord 已重新加载插件并配对，在深色主题下检查了实际浅色译文；未改变用户的频道自动模式设置，Bridge 保持运行。

## 网页失败提示与模型 JSON 围栏（2026-10-14）

用户在普通 Chrome 的 LLVM 页面报告每段出现原生“翻译失败，重试”按钮。单段真实重试显示 `Unexpected token`，响应以 Markdown JSON 代码围栏开头，旧解析器直接解析整个字符串而失败；这笔失败仍记录 225 Tokens。共享解析器现仅剥除完整的单层 JSON/无语言代码围栏，继续校验 JSON 结构、段落 ID、已有允许元数据及代码/公式保护标记，拒绝围栏外说明文字和非法字段，不自动追加付费重试。

整页/自动失败仅在悬浮面板汇总数量与原因，原文中不插错误按钮；显式单段失败提供继承主题的小型重试入口，标题和无障碍名称包含原因。失败状态独立保存，防止观察器或暂停/恢复自动重复请求；手动重试在暂停状态也有效。

本机已更新浏览器产物与安装的 Bridge 快照，正常退出两端后停止已确认的旧服务并更新，再打开原 Chrome 配置档与原 Discord。普通 Chrome 同一 LLVM 首段成功显示原文下方中文译文，216 Tokens、约 ¥0.000390；自动翻译保持关闭。此前失败和未知用量均保留。单元测试覆盖围栏兼容、拒绝额外说明/非法字段、整页错误不改布局以及暂停后手动重试；共享改动通过两端构建与浏览器回归，不声称本轮再次验证了 Discord 真实模型翻译。

## 输出额度与网页分批（2026-10-14）

官方当前 Flash 的上下文长度为 1M、最大输出为 384K，见 [DeepSeek 模型规格](https://api-docs.deepseek.com/quick_start/pricing/)（2026-10-14 核对）。上下文容量不等于单次请求的 `max_tokens`；本机保留的测试配置仅允许输出 512 Tokens，网页旧批量器按 4,000 输入字节/最多 16 段合并，因而出现 `Model output limit reached`。项目默认输出额度从 2,048 调整到 4,096，本机通过已认证的 Provider 配置接口更新并确认实际生效值为 4,096，不改 Key、供应商、端点或预算。

网页批量器读取后台提供的输出额度，结合字节上限保守分批；这只是估算，不是供应商 tokenizer 的精确预测。长段落在完整 Markdown 链接/强调以及代码/公式保护标记边界分块，再恢复到原段落的一个译文中。不可安全切开的长 Markdown 原子仍独立处理，供应商仍可能拒绝或截断。分块请求保持最多两个并发，各自通过原有预算/用量接口；合并展示汇总每块 Tokens 与费用，不重复计算同一批费用。失败不自动重试，并取消该段未完成分块；未知用量仍遵守原严格预算保护。

回归测试覆盖 512 输出额度下的批量限制、长段落通过真实共享保护/恢复逻辑后保持 Markdown/链接/代码/公式、拼接空白与原 ID、分块账目相加、失败取消后续分块。126 项单元测试与 14 项浏览器端到端测试通过，1 项可选联网测试跳过。原 Chrome 扩展已更新；真实 LLVM 可见段落验收被 `Token budget exceeded` 拦截，恢复自动关闭，没有新增请求记录：验收前后均为 63 条、25,954 已知 Tokens、1 条未知记录。故不声称本轮真实整页翻译成功，未清空统计或提高每日预算。

## 原生 Pi 翻译会话与模型容量（2026-10-15）

共享 Bridge 直接复用 Pi 1.2.0 的 `AgentSession`、内存 `SessionManager` 和自动压缩。网页按来源、标签页、文档与 URL 摘要隔离；Discord 按来源、账号和频道隔离，目标语言/术语不同也不混用。Ask Pi 独立，移除旧的 20 轮应用上限。同一范围串行，不同范围可并行；本地结果缓存、长段落分块、预算和未知用量保护保留。浏览器可选直连模式仍不提供 Bridge 的原生会话与压缩。

官方 [模型元数据接口](https://api-docs.deepseek.com/api/list-models/) 的已授权免费查询于 2026-10-14 返回当前 Flash 的 `context_window=1048576`、`max_output_tokens=393216`。上下文包含输入和输出；接口未单独发布最大输入值，因此不虚构该字段。Bridge 初始化查询官方端点，失败时回退到带核对日期的官方快照；其他模型采用供应商元数据或 Pi 目录。兼容端点规格未知则明确拒绝猜测。`maxOutputTokens=0` 为按任务自动分配，正值为用户主动选择的请求额度，均受真实容量约束。任务分配与预算估算仍不是精确 tokenizer。

使用真实 Pi SDK 与本地模型 fixture 验证历史前缀复用、跨页面/频道/Ask 隔离、排队取消、自动压缩、摘要预算拒绝后不继续生成、被拒回合不堆入后续上下文、Ask 超过 20 轮，以及用量保存失败时流能结束。每次模型请求（包括摘要）都有独立记账入口；供应商缓存是否命中由其响应决定，历史前缀相同并不保证命中，见 [官方缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)。

本轮本地回归不使用真实推理，不证明真实 1M 长上下文或缓存收益。已有 63 条用量记录、25,954 已知 Tokens 与 1 条未知记录不清除，预算不提高；此前真实翻译已被预算保护拦截。当前开发产物尚未安装到正在运行的原 Chrome/Discord 服务快照，需两端退出后统一更新 Bridge、Native Host 与插件，再进行客户端验收。

升级须同步更新两端和服务，以识别新增的可选模型规格与用量 `purpose` 字段；既有正数输出额度保留为显式选择，不自动改成零。协议传输和安全校验保留，正文与压缩摘要仍仅存内存。规格来源和实现边界见 [架构说明](architecture.md#翻译会话与供应商额度2026-10-14)。
