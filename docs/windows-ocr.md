# Windows 本地 OCR 选型与评测设计

2026-10-21 · 所有选型为待验证建议，本轮未运行引擎或下载模型。流程见 [产品规划](windows-product.md)，隔离边界见 [模块设计](windows-modules.md)，阶段要求见 [验收计划](windows-acceptance-plan.md)。

## 推荐路线

优先验证 **PaddleOCR 轻量检测/识别模型 + ONNX Runtime CPU + Rust 工作进程**。首轮候选为 `PP-OCRv6_small_det` + `PP-OCRv6_small_rec`，同时比较 tiny 检测与轻量识别组合的速度/错误，保留 `PP-OCRv5_mobile_det` + `PP-OCRv5_mobile_rec` 作为兼容基线。W0 才锁定具体模型，不能先宣称 v6 在桌面截图上最好。

截至本次核对，官方检测/识别表已列出 v6 small/tiny，且注明 v6 与 v5 部分指标使用不同测试集，不可直接比较。v5 文档有 ONNX Runtime 路径，不能据此推断任意 v6 导出模型、算子和 Rust 后处理都已兼容。[检测模型](https://www.paddleocr.ai/latest/en/version3.x/module_usage/text_detection.html)、[识别模型](https://www.paddleocr.ai/latest/en/version3.x/module_usage/text_recognition.html)。

模型推理在 Rust worker 中通过 ONNX Runtime 执行；`ort` 作为 Rust binding 候选，不是 PaddleOCR 官方 Rust SDK。需验证 binding、原生 runtime DLL、ONNX opset、模型 I/O 与 CPU 指令要求的一组锁定版本。[ort 项目](https://github.com/pykeio/ort)、[ONNX Runtime 兼容性](https://onnxruntime.ai/docs/reference/compatibility.html)。本方案没有要求推理库本身也必须纯 Rust。

## 候选比较

| 候选                          | 优势与使用理由                                           | 必须验证的代价/限制                                           | 建议地位                                   |
| ----------------------------- | -------------------------------------------------------- | ------------------------------------------------------------- | ------------------------------------------ |
| PP-OCRv6 small/tiny + ORT CPU | 可控制模型、语言、检测与识别流程，便于跨平台复用推理逻辑 | ONNX 导出/算子、字典、预后处理、模型许可证、DLL 与资源消耗    | 优先验证，不提前宣称胜出                   |
| PP-OCRv5 mobile + ORT CPU     | 有公开部署与模型基线，便于校验转换链                     | 截图小字、混排和段落顺序仍需实测                              | 对照与降级候选                             |
| Windows.Media.Ocr             | 使用系统 OCR，提供行/词几何信息                          | 桌面包身份、语言包、Windows build；引擎结果和跨平台行为不可控 | Windows 备选，不能在无包身份安装中直接调用 |
| Tesseract 5                   | 本地运行，布局/语言选项明确，易建立对照                  | 页面分割、缩放和输入质量显著影响输出，中英文截图需调优        | 实测对照，结果更优才采纳                   |
| 多模态云模型或大型本地 VLM    | 可辅助复杂文档理解                                       | 图像外发或显著资源需求、延迟/费用、几何定位不稳定             | 首版不作为默认 OCR                         |

Windows API 约束以 [Windows.Media.Ocr 文档](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr?view=winrt-26100) 为准；Tesseract 的输入质量与分割建议见 [官方质量指南](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html)。引擎适配器保留可替换边界，首版默认只部署一个经选型的本地引擎，不为对照测试把所有引擎都塞进安装包。

## 从截图到段落

1. **截图与几何**：记录 captureId、显示器、捕获时间、物理选区和逻辑坐标变换；处理多屏负坐标、混合 DPI、旋转与跨屏选区。不能捕获时明确失败，不用旧截图继续翻译。
2. **输入约束**：校验尺寸、像素格式、像素数量上限。过大选区提示缩小或分块，禁止不告知地缩到文字不可读；首轮上限建议 16 MP，W0 测试后固定。
3. **检测**：输出文字四边形与坐标映射，保留缩放/padding 参数；不能将 resize 后坐标直接用于屏幕定位。
4. **识别**：裁剪/校正检测块，按模型实际色彩顺序、归一化、字典和解码方式执行。方向分类仅在样本证明需要时加入，首版不启用重型文档去扭曲/版面分析链。
5. **整理**：按行高、间距和列边界推断阅读顺序；保留显式换段与代码缩进，不跨列拼接。表格/复杂多栏标记布局不确定，展示块并允许修正。
6. **用户修正与翻译**：保留识别原文与修订稿，修改后新 revision 重新翻译；OCR 置信度只反映引擎输出，不等于翻译可信度，不由 LLM 暗中改写识别内容。

OCRResult 记录 engine/model/dictionary/preprocessing 版本、blocks、polygon、order、可选 confidence、语言提示与阶段耗时。没有提供的置信度填 unknown。截图和未提交结果仅存内存；清理路径覆盖成功、失败、取消、worker 崩溃和应用退出。

## 运行与分发

CPU 为必须通过的基线，不要求独立显卡、NPU、CUDA 或 DirectML。GPU 加速留待实测有必要后独立评估，不能让普通电脑退化为不可用。

运行时不依赖 Python/Paddle 环境。若需转换模型，转换工具仅在构建/模型准备阶段运行，记录官方权重来源、转换脚本版本、opset、字典和 SHA-256，并用相同图像对比转换前后结果；不下载来源不明的第三方 ONNX 就宣称官方兼容。

默认安装携带首版中英文 OCR 所需固定模型和 runtime，支持联网翻译前的本地识别。若总包体不能满足 W0 分发预算，需把按需下载作为明确产品变更：显示下载大小、进度、校验和失败恢复，提供离线资源包。不能在用户点击框选后静默下载或切换到云 OCR。

首版语言验收为简体中文、英文和中英混排；模型声称更多语言不等于本产品均验收。模型与代码许可证分开核对，包括检测/识别权重、字典、runtime DLL、转换后权重和 notices。固定本地资源校验失败时拒绝载入并提示修复，不通过关闭校验继续推理。

worker 默认并发 1，建议空闲 60 秒释放模型或退出，值待资源测量固定。取消先停止后续处理并丢弃旧结果；native 推理不可中断时到截止时间结束 worker，核心进程保持响应。首次/热启动和模型卸载后再次调用分别计时。

## 同一数据集的评测

构建 **160 张非敏感截图**，每类 20 张：英文段落、中文段落、中英技术混排、小字号 UI、深色主题、扫描 PDF、双栏阅读、表格/代码混合。覆盖 100%/125%/150%/200% 缩放；记录应用与字号、字体、来源和使用许可，人工标注文本块、原文及阅读顺序。

120 张用于配置/阈值调优，40 张冻结为验收集且每类 5 张；分割按来源文档隔离，不能把同一页面换个缩放就放进两边。另补空白、极端尺寸、损坏图像与受限截图作为故障集，不混入文字精度分母。真实敏感内容不进入仓库。

| 指标           | 统计方法                                                                                      | 初始准入目标，W0 验证后冻结                                      |
| -------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 字符错误率 CER | `(替换+删除+插入)/参考字符数`；保留标点/大小写，只统一约定空白；报告按类别/语言分层和总微平均 | 清晰单栏中/英/混排 CER ≤3%；每类均需达标，不能用英文掩盖中文错误 |
| 困难样本 CER   | 小字/扫描/暗色分别统计，双栏按块匹配后计字符                                                  | 每类 ≤10%；超限须限制支持范围并提供修正，不能标为高质量通过      |
| 检测召回       | 标注块 IoU≥0.5 的一对一匹配比例，漏块计入                                                     | 清晰文本 ≥98%，困难样本 ≥90%                                     |
| 阅读顺序       | 标注先后关系中被逆序的比例，另列跨列错误                                                      | 普通单栏无跨段乱序；双栏逆序比例 ≤5%，复杂表格可提示不支持       |
| 延迟           | 同一 CPU/Windows build，区域≤1920×1080、≤30 行；全链包含输入整理与后处理                      | 热启动 p95 ≤1.5 秒，冷启动 p95 ≤3 秒；模型推理时间单列           |
| 稳定性         | 反复识别/取消/重建，监控进程和句柄                                                            | 200 次任务、50 次取消/故障，无崩溃扩散、卡死或旧结果覆盖         |

以上是工程目标，不是官方数据或已达成结果。报告每个引擎的字符错误、样本数、失败率、包体/内存、耗时分布及具体模型，不只报平均值。公开模型 benchmark 不能替代本地截图评测。

## W0 的选型输出

形成 OCR ADR：默认引擎和具体模型/字典、转换与 runtime 版本、语言范围、许可证、安装/离线方案、实际质量/延迟/资源和已知失败样本。只有全部硬约束通过才确定默认；若 v6 的实际部署链不稳而 v5/Windows OCR/Tesseract 更适合，就按结果选，不追逐版本号。尚未运行测试时所有候选保持“未验证”。
