# 原 Discord 客户端验收

日期：2026-10-14；macOS 27.0.1 / Apple M4。使用用户已有的 `/Applications/Discord.app` 和 LingoSofa 测试服务器，没有另开客户端。用户明确授权安装 Vencord，以及发送、编辑、删除合成测试消息；不读取 Discord token，不发送其他频道历史或附件。

## 实际版本与安装

- Discord stable 636431（a5d0242），0.0.415 arm64（93145）。
- Vencord 16ec4ea838899706019e7f472e45f055070abeb1（Standalone）。
- Electron 42.11.10；Chromium 148.0.7778.280。
- 用户通过官方安装器完成原客户端安装。随后在备份原 Vencord 构建后加载本仓库经 `npm run verify:vencord` 验证的插件构建。
- LingoSofa 已在 Plugins 中启用，配对令牌仅为此次临时测试凭证。DeepSeek Key 只由本地 Bridge 从被 Git 忽略的 `.env` 加载，没有填入 Discord。

## 真实交互结果

| 检查           | 观察结果                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| 手动翻译       | 消息菜单有翻译与问答入口；原文保留，消息下方显示中文译文，`fetch()` 保留                                 |
| 自动翻译与编辑 | 明确启用测试频道自动模式后，将消息中的 URL 改为 updated URL；译文更新为“读取更新的 URL”，不展示旧结果    |
| 多轮问答       | 第一问识别 `fetch()`；第二问读取同一会话内容并回答“读取更新后的 URL”；清理后回合和会话汇总消失           |
| 100 次频道切换 | 在 #常规 与空测试频道间完成 100 次实际切换，每次确认目标频道标题；回到原频道仅有一个译文，无新增模型请求 |
| 草稿预览与复制 | 预览同一合成文本复用译文；点击复制后粘贴到预览字段核对中文内容，没有自动发消息                           |
| 用量明细       | 实际 token、估算费用、耗时、TPS，以及官方价格来源、峰时状态和 2026-10-14 核对日期可见                    |
| 清理           | 清理会话和本地配对；关闭自动频道；删除获准的合成测试消息，确认消息不再出现                               |

## 两端共用 Bridge 与取消

另一次测试中，临时 MV3 浏览器 profile 经实际 Native Host 与原 Discord 同时连接同一个 Bridge，`shareUsage` 和 `shareBudget` 均保持默认关闭。

- 浏览器仅预览“blue sofa”合成段落，回答 Blue；119 input / 1 output / 120 tokens，估算 USD 0.0000369。
- Discord 仅选择含 `fetch()` 的测试消息，正确回答该函数；128 input / 7 output / 135 tokens，估算 USD 0.0000468，没有混入浏览器上下文。
- 浏览器用量面板状态仅返回 web 记录。通过同一 Bridge 的公开用量接口检查，浏览器预算使用 120 tokens，Discord 预算独立。
- Discord 发起长回答并点击停止，显示取消错误，无晚到回答。取消记录的 usage 为未知；Discord token/费用预算显示未知并暂停，浏览器仍保持已知用量且没有警告。不能把取消请求计为免费。
- 发现取消后旧会话统计仍留在界面，已修复两个前端的新请求流程，并以真实 MV3 UI 的回归测试验证成功 → 待处理 → 取消时旧汇总消失。修复后的完整 Vencord 集成检查通过，构建已更新到原客户端；此修复的取消回归证据来自浏览器自动测试，未追加真实付费 Discord 请求。

## 清理与验证边界

两次临时 Bridge 均已停止，临时浏览器 profile、Native Host 注册与配对文件已清理，Discord 内配对令牌已清空。用户选择保留空频道 #lingo-sofa-acceptance，已保留。原客户端保留启用的 LingoSofa 插件；后续使用需启动自己的 Bridge 并重新配对。

以上是一个账号、两个测试频道和合成文本的实际验收。多账号切换、长频道的真实虚拟滚动、Windows、读屏和公开分发许可仍没有真机证据，见 [总验收记录](acceptance.md)。

## 内嵌双语与轻量控件回归（2026-10-14）

在同一原 Discord / Vencord 版本的 LingoSofa 服务器完成。插件通过宿主 `chatBarButton` 接口加载，冷重启后入口可见；开发者工具仅查看日志，未输入或执行控制台命令。Discord 的“诈骗信息”文字是控制台自身的防粘贴代码提示，不是聊天消息。

- 页边 44px 入口展开/收起正常，语言、频道自动模式、只显示原文在轻量面板，配对/用量另开；输入框保持原样。
- #常规 的获准合成消息手动翻译后，译文直接在原文下方，无卡片；`fetch()` 保持在原消息。隐藏/恢复显示已有译文；编辑后旧译文清除，新译文反映 updated URL；删除后原消息与 accessory 一同清理。用户原有消息未作为测试数据删除。
- 保留的 #lingo-sofa-acceptance 空频道开启自动模式，合成新消息和编辑均自动翻译。发现发送中的临时消息/正文未变化更新可能重复派发，已修复：等待 SENT，只有正文变化才使缓存失效。控制器回归覆盖临时发送、元数据更新、真正编辑、代码排除与跨频道暂停。
- 修复后以全新临时 Bridge 冷重启验收：新消息只有 1 次成功模型调用，编辑后累计 2 次；共 267 tokens、USD 0.00007065 估算费用，均按请求开始时官方谷时价格。首条 132 tokens；两次之间与之后切换频道，译文不混入其他频道，返回可恢复已有译文。此费用没有供应商账单对账。
- 关闭测试频道自动模式，删除获准合成消息，保留测试频道；临时 Bridge、私有目录和配对文件在退出时清理。API Key 仍由用户的被忽略 `.env` 管理，没有复制进插件或仓库。

首次修复前临时 Bridge 有 5 次成功记录、632 tokens、USD 0.0003282 峰时估算，包含操作者主动翻译的短消息和重复自动调用；保留这一失败证据，不将其计为去重通过。修复后的两次独立记录才作为新消息/编辑去重验收。

新的选区 Ask Pi 已在原客户端实测：明确选中合成消息中的 `LingoSofa`，悬浮入口先预览该单词，未扩大为整条消息；点击提问后 DeepSeek 返回同一词，Pi 会话汇总为 110 tokens / 3 条消息，清理后回答和汇总消失。点击控件时 Discord 会恢复输入框焦点，首次验收发现选区丢失，已修复为保留最近一次明确选择供只读预览；账号/频道变化清空选择，正文变化禁止发送。最终独立 Bridge 总计 3 次模型调用、377 tokens、USD 0.00008895 谷时估算，包含前述两次翻译与一次问答。

本轮未完成多账号、只读频道、长频道虚拟滚动或读屏验收。网页新入口已通过实际 MV3 E2E；Discord 键盘/拖动实现存在，本次未取得完整可观察键盘/读屏证据。其他环境条件见 [发布准备](release-readiness.md)。
