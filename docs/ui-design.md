# 内嵌双语与轻量入口

日期：2026-10-14。依据用户确认的网页/Discord 静态参考图与“悬浮入口 + 轻量菜单”选择实施；静态草图不作为真实验收。

## 阅读主体

单段或段内选区翻译直接插在对应原文下方，继承网页字体和颜色，保持不透明度，不套译文卡片、不替换原文。整页模式逐段应用，只调度可见正文及附近内容；链接、内联代码、代码块与输入框保持原有结构。段落修改、隐藏或删除会清除失效译文；暂停保留已完成译文，中止未完成任务，晚到结果不会插回。跨段选区、复杂非正文结构可能降级为明确错误，不能宣称任意布局均支持。

## 网页入口

扩展主按钮为“在页面中打开控制”，打开时不发送正文。网页与 Discord 统一使用 44px 页边入口和 320px 面板：品牌/网站标题、双语阅读总开关、目标语言、当前供应商模型、底部自动翻译开关。入口可拖动吸附两侧、方向键上下移动、Escape 收起，面板依据可用空间选择上下展开并滚动。日常面板不再放整页按钮、原文恢复、进度条或更多操作；手动整页/恢复和问答留在扩展辅助入口，段落悬停仍可就地翻译。

悬浮入口在已获网页访问权限的 HTTP/HTTPS 页面默认出现；首次安装打开设置页引导授权，扩展弹窗也提供同一入口。授权仅显示阅读控件，不开启自动翻译、不发送正文。自动模式按网站保存；悬浮开关本身就是用户对当前网站自动翻译的同意，不再打开额外的应用确认页。已有访问权限时直接启用，缺少权限时从该次点击请求 Chrome 原生访问权限，拒绝则不开启。停用保留已完成译文，取消该网站在途任务，不影响其他网站；暂停期间仍能显式翻译单段。语言或模型切换重新应用已授权网站的可见正文。

设置首页现采用独立的 AI 工作空间，侧栏区分翻译模型、Ask 默认模型与供应商账户，使用用户品牌的绿色强调、中性色表面及深浅主题。模型偏好复用所选账户的地址；账户编辑页可修改地址，新端点需重新配置 Key。浏览器直连保留 DeepSeek/OpenAI 兼容能力，其他 Pi 供应商可通过本地助手选择。直连账户保存在 trusted local storage，Bridge 多账户与独立默认值保存在本地 0600 的 accounts.json。用量、预算、术语与历史放在独立辅助页，扩展弹窗的设置链接打开新的 Provider 首页。

Ask Pi 使用独立对话框，先显示只读选中上下文，点击提问才发送；关闭清理会话。发送前与回答返回时均验证上下文，原文变化不显示晚到回答。入口位于辅助页面，不占三项悬浮面板。网页合成事件不能触发模型切换、自动授权或翻译；内容脚本仅获得 Ask 选择器所需的公开账户和模型元数据，不持有 API Key 或账户余额。

## Discord 入口

单条消息沿用消息悬停工具栏 / 右键菜单的翻译按钮，译文在原消息下方，回复、表情与代码仍属于原消息。纯代码块不发起翻译，混合消息仅发送代码块外的正文。成功译文的操作收在省略入口，日常不占据独立卡片。

频道边缘 44px 入口可拖动，展开后只显示目标语言、模型和自动翻译此频道。自动模式按账号与频道授权，只处理新消息和可见历史，不读取全部历史；停用取消在途工作并保留完成的译文。问答和辅助操作不占用日常悬浮面板。

控件通过 Vencord 的 `chatBarButton` 接口在宿主 React/store 就绪后挂载；没有可用输入栏的只读频道可能不显示悬浮入口，消息菜单作为备用。此限制仍需真实只读频道验证。选区问答保持选中范围，校验完整原消息用于检测编辑，不将完整原文自动扩大发送。输入框不被替换，不自动发送草稿。

## Discord Provider 设置

插件配置页只保留供应商、模型及 API Key。采用单一连接面板：品牌标题与连接状态、供应商/模型并列选择、凭据输入、底部保存与反馈。窄屏改为单列，沿用 Discord 深浅主题变量，键盘焦点与错误状态清晰可见。标准模型地址由 Pi 模型目录填充，仅自定义 OpenAI 兼容供应商显示地址输入。

所有频道均可手动使用，无需填写频道 ID；自动双语仍按频道显式开启，仅处理新消息与可见历史。语言仅在悬浮入口设置。内部持久化语言/频道偏好继续使用宿主设置，但隐藏自动生成的设置表单。端口和短期配对信息由桌面 native helper 从本地助手的 `discord-connection.json` 读取；不扫描其他目录，也不读取 Discord 认证或模型 Key。旧助手的手动配对仅保留在用量/草稿面板作为兼容入口。

Provider 目录和保存接口均要求现有来源白名单、短期令牌、Host 校验；仅 Discord 和明确列入白名单的扩展来源可使用；网页不能调用完整 Provider 配置接口。Key 通过认证的 loopback 请求送到 Bridge，以多个命名账户保存于权限 0600 的 `accounts.json`，不写入 Vencord 设置；目录只返回公开账户元数据。翻译与 Ask 默认值分别保存，每个 Ask 会话单独覆盖模型；切换账户不会清空其他会话，选择器提示新供应商将收到本会话历史。翻译请求在途时拒绝更改其运行时；Ask 默认值与不相关账户可独立保存。使用 Pi 登录仍需在 Bridge 中显式启用。

## 悬浮频道控件精简（2026-10-14）

按最新需求，Discord 悬浮面板只提供三个控件：目标语言、当前供应商的模型、自动翻译此频道。移除更多操作、原文显示、Ask Pi、用量/草稿和 Provider 跳转；Provider 配置保留在 Vencord 插件设置，消息级 Ask Pi 保留在消息菜单/译文操作中。此调整取代上文对 Discord 悬浮面板的旧描述。

320px 面板采用品牌与频道标题、两行统一高度的下拉框、底部带简短范围说明的开关。长频道名省略，边框与文字沿用宿主主题，窄屏限制面板宽度，高度按入口上下可用空间限制并允许滚动，关闭与 Escape 返回入口焦点。语言提供常见选项并保留已有自定义值，切换时取消当前频道旧请求，自动模式更新可见消息，晚到的旧语言结果不能覆盖新译文。

模型只切换当前已配置供应商，沿用已有端点与凭据，不在悬浮面板跨供应商切换。保存失败保留旧模型，忙碌时禁用控件；切换成功清理旧译文，通知消息组件重新观察可见内容。自动开关使用实际自动配对的 Bridge，不再要求填写手动令牌；关闭后停止在途翻译并保留完成的译文。

## 译文分隔与格式

网页正文、选区译文与 Discord 消息译文统一在上方使用轻量分隔线和少量间距，继承主题文字颜色和原文字体，不套独立卡片。支持粗体、斜体、删除线、列表、引用、链接、表格及代码的 Markdown 显示；标题保持正文大小，避免打乱原页面层级。

共享翻译层将行内代码、多重反引号、反引号/波浪线围栏及缩进代码块替换为保护标记，返回后逐个验证并还原；修改或丢失标记拒绝显示。Discord 混合消息只翻译代码块之外的正文，纯代码消息跳过；网页跳过 pre、纯 code 段落及代码内部选区，混合段落保留代码原文与链接结构，链接标签参与翻译。没有语义标记的普通文字不使用猜测规则强行判定为代码。

两端使用同一 Markdown 渲染器：原始 HTML 显示为文字，链接只允许 HTTP/HTTPS/mailto，图片仅显示标签，不加载远程资源。译文内生成的列表/表格不参与原文重新提取，暂停、编辑失效清理及恢复原文继续有效。`tests/markdown.test.ts` 覆盖格式、保护标记、代码跳过和不可信输出；实际 MV3 及 Discord 深浅主题浏览器测试检查 Markdown 和分隔线。原 Discord 客户端的真实模型回归已完成，宿主重置样式导致的列表标记缺失及紧密行距已修正，见 [客户端记录](discord-acceptance.md)。

## 译文用量与费用

网页段落、选区译文和 Discord 消息译文末尾显示一行小字，例如 `265 Tokens · ≈ ¥0.001073`，沿用主题颜色，不加入日常悬浮控件。鼠标停留可查看计量范围、美元原值、人民币换算说明、价格来源和核对日期。未知 Token 或未知价格分别显示未知，不能当作免费；极小的正费用显示小于 ¥0.000001，避免被四舍五入成零。

供应商只提供请求级计量。单条请求显示该请求用量；网页合并请求显式显示“同批 N 段合计”，各段展示同一批实际用量，不将它伪装成每段单独计量，也不能逐段累加。混合缓存批次只统计本次实际发送的段落；缓存段落显示“缓存命中 · 本次 0 Tokens · ¥0”，不代表此前翻译免费。预算和全局统计继续以实际请求记账，展示不增加计费记录。

## 人民币展示与数学公式

费用默认显示人民币，按 [国家外汇管理局中间价表](https://www.safe.gov.cn/AppStructured/hlw/RMBQuery.do) 的 2026-10-14 快照折算：100 USD = 672.49 CNY，即 1 USD = 6.7249 CNY。[官方标价说明](https://www.safe.gov.cn/safe/rmbhlzjj/index.html) 明确美元等币种以 100 外币折合人民币。用量提示保留美元原值、汇率数值、来源、日期及“非实时牌价”的说明；不是银行实际换汇或供应商实扣。历史、供应商单价与预算仍以 USD 记账，不更改原有额度含义。未知费用继续显示未知，极小正值不显示为零。

译文支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`。共享核心保护完整公式，模型返回后验证并原样还原；公式渲染在 Markdown 处理前隔离，防止表格竖线或反斜杠破坏数学内容。普通金额、转义美元符号、代码中的公式不参与数学排版。网页已有 MathML、KaTeX/MathJax 公式保留原处，其内部文字不进入正文提取；源码形式的公式在译文中就地排版。

KaTeX 0.19.0 仅生成原生 MathML，使用宿主数学字体，不加载字体或 CSS CDN。默认不信任公式，禁用可加载外部资源/修改 HTML 的命令，限制宏展开、尺寸和公式长度；每次渲染使用独立宏环境。无法解析或不支持的 TeX 以原始文本显示。数学排版依赖宿主原生 MathML；Chromium 深浅主题和原 Discord 的检查不能代替其他系统或读屏验收。

## 双语阅读总开关（2026-10-14）

两端悬浮面板在标题下提供“开启双语阅读”开关。关闭会取消正在进行的翻译和问答、移除本端译文并恢复原文，同时禁用语言、模型与自动翻译控件；入口仍可点击。重新开启保留语言、模型及网站/频道的自动翻译偏好，有自动授权时重新处理可见内容。状态在本端保存，网页各标签同步，Discord 各频道共享。它不会释放客户端的服务连接，也不会改变另一端的阅读开关。自动翻译开关仅控制当前网站/频道的自动处理，关闭后仍可手动翻译，已有译文保留。

## 网页段落格式修正（2026-10-14）

原网页源码的缩进与换行不等于阅读换行。提取时把普通文本的空白规范为行内空格，保留 `br` 的显式换行；网页 Markdown 渲染将软换行作为连续正文，Discord 的消息换行语义保持原状。源段落的加粗、斜体、删除线和行内代码转为对应 Markdown，原文节点不改写。代码与公式仍受保护。

链接标签不再作为“不可翻译内容”。源目标地址存于本机段落状态；模型仅收到标签和不透明目标标记，返回后经保护标记验证，再由网页恢复 HTTP/HTTPS/mailto 目标。目标地址只在链接渲染时还原，不参与 Markdown/公式解析，危险协议降级为普通文字。源链接目标或强调结构变化也会使旧译文失效，避免文字没变却显示旧链接。

在普通 Chrome 的现有 LLVM 首页，实测翻译 Clang 段落：旧译文有 9 个强制换行、四个链接的文字未翻译且链接丢失；新译文没有源码强制换行，按当前宽度自然排成三行，保留四个链接及源强调结构，“错误和警告信息”“Clang 静态分析器”可翻译。段落仍显示 376 Tokens、约 ¥0.000791；本次只手动触发单段，没有启用整页自动翻译。字体继承属性与原文一致，中文实际字形由浏览器字体回退决定。

回归覆盖源码折行与显式换行、链接标签/目标保护、隐藏代码内容排除、危险 URL、含括号 URL、代码与公式、原文恢复、链接变更的晚到结果清理，以及实际 MV3 的段落和 1,000 段压力测试。原文和译文中都可有行内代码节点，测试分别核对源节点和译文节点，不再将新增译文代码误判为源代码重复。

## 段落旁 Ask 与直接快捷键（2026-10-15）

网页与 Discord 统一使用 Alt Shift A（macOS 为 Option Shift A）直接打开 Ask：优先使用当前正文选区，否则使用鼠标所在的正文段落或 Discord 消息。输入框、可编辑区域与 Ask 自身不响应该快捷键；打开不发送模型请求。Esc 关闭。网页原有 Alt L 继续打开悬浮快捷菜单，消息右键与既有 Ask 入口保留。最初尝试的 Alt A 在本机与另一款翻译扩展冲突，最终快捷键已避开该组合。

此次已在原 Chrome 的 LLVM 网页和原 Discord 测试频道实测新快捷键，确认上下文预览、单层标题与旁侧窗口可见，没有提交 Ask 提问。位置翻转、窄屏、滚动跟随、来源删除、输入区排除、非可信键盘事件及原有选区上下文校验均有回归覆盖。
