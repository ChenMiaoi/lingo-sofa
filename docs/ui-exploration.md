# 阅读现场入口设计探索

日期：2026-10-14；状态：探索与交互草图，尚未确认最终方案。用户明确要求网页与 Discord 都有悬浮式入口，并要求先探索交互，再继续实现。此前提交的设置/用量面板是辅助界面，不等同于日常阅读主入口；暂停新增产品 UI 实现。

## 参考依据

- [沉浸式翻译官方使用说明](https://immersivetranslate.com/docs/usage/)提供页边快捷入口、浏览器工具栏、快捷键和段落操作，设置另行进入；[官方 FAQ](https://immersivetranslate.com/en/docs/faq/)也提供关闭浮球的选项。借鉴的是阅读现场操作与可退出机制，不能据此证明浮球适合所有用户。
- [Chrome 官方 Side Panel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)提供与主页面并行、可持续打开的扩展内容区域。它适合作为持续问答候选，但跨标签页保持界面不意味着可以跨页面继承问答内容。
- [Discord 官方消息编辑说明](https://support.discord.com/hc/tr/articles/207618817-How-do-I-edit-my-messages)沿用消息旁的悬停工具栏。插件已有对应宿主入口，应优先把单条消息操作绑定在消息上，而不是让一个全局浮球猜测当前发送范围。

以下取舍是针对 LingoSofa 的设计判断，不是来源产品的验证结论。

## 三种交互候选

| 候选                | 主要任务                  | 优点                                             | 代价 / 必须检查                                                     |
| ------------------- | ------------------------- | ------------------------------------------------ | ------------------------------------------------------------------- |
| 悬浮入口 + 轻量菜单 | 整页/频道控制、短问答     | 易发现，不需要先离开阅读界面；平时只占一个小入口 | 展开后可能遮挡正文；需边缘停靠、隐藏、键盘退出与工具栏备用入口      |
| 内容旁快捷操作      | 选区或单条消息的翻译/解释 | 发送范围明确，操作距离短                         | 发现性弱，不能只依赖鼠标悬停；菜单应避免覆盖选中文字和消息          |
| 悬浮入口 + 持续侧栏 | 多轮问答、较长回答        | 上下文与回答可持续查看，减少重复弹窗             | 占用阅读宽度；需窄屏降级、焦点恢复，且页面/频道切换不能混入旧上下文 |

## 当前推荐方向

采用分层入口，而非让用户在设置页里完成日常阅读：

- 网页：一个页边悬浮入口负责当前页面，划词/段落旁入口负责局部内容；问答前显示本次发送范围。
- Discord：消息工具栏负责这一条消息；频道边缘入口负责自动翻译状态、暂停与本地连接。全局入口未选择消息时不能直接询问某条内容。
- 短操作使用轻量菜单；多轮问答可展开到持续侧栏。完整模型配置、历史筛选、计价解释留在辅助页面。

两端共享视觉语言、状态和快捷操作顺序，定位与宿主交互分别适配。不自动派发、不扩大上下文、不覆盖原输入框；隐藏浮动入口后仍须有可恢复的宿主入口。

## 先验证再实现

交互草图仅使用合成内容与本地模拟回答，不调用模型、不读取真实网页或发送 Discord 消息。比较入口发现性、完成翻译所需步骤、遮挡面积、上下文确认、退出/隐藏和连续问答，再确定方案。后续实现应覆盖：无配对/无密钥、未选中内容、请求中/停止/失败/预算暂停、编辑/切换导致上下文失效、键盘/读屏、缩放/窄屏与宿主控件碰撞。
