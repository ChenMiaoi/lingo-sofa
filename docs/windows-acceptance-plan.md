# Windows 独立桌面版阶段验收计划

2026-10-21 · **W0 总体未关闭；桌面闭环和部分跨应用能力已有实现。** 本文定义完整阶段门槛，阶段编号不表示各项开发必须串行。实际结果与未通过项统一见 [验收状态](acceptance.md)，不能把目标表当作完成记录。

设计依据：[产品规划](windows-product.md)、[技术方案](lingo-sofa-plan.md)、[模块设计](windows-modules.md)、[模型与 OMP](windows-models-and-pi.md)、[OCR](windows-ocr.md)。

## 通用规则

每阶段需有范围、构建 commit、Windows build、CPU/RAM/GPU、显示器/DPI、依赖/模型版本、步骤、预期/实际、脱敏证据、失败项和负责人。自动模拟、真实桌面操作、真实供应商请求分别标记。

状态只用未开始、进行中、通过、失败、环境受限。环境受限/跳过不等于通过；阶段有必需项未通过就不能关闭。允许在通过前准备下一阶段的独立任务，但不得把总体门槛标为完成。没有用户凭证时先用固定数据验证协议，真实认证项仍保留待验；不得自动读取别的应用凭证。

涉及用户能力删减、改成在线 OCR、改变随包 OMP/Bun 的运行边界或扩大支持范围时，先修订评审中的产品/技术方案。固定模型、依赖和验收阈值后变更，重跑实际受影响项；不为通过检查临时放宽阈值或关闭规则。

## W0：关键能力与架构定案

| 编号  | 必需验证     | 通过标准与证据                                                                                                                                        |
| ----- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| W0-01 | UIA 选区读取 | Chrome、Edge、Discord、一个 PDF 阅读器、一个编辑器各记录选区支持；至少浏览器+一个桌面应用成功取文，其余有明确的复制/OCR 降级，不错读整窗              |
| W0-02 | 辅助进程故障 | 注入无响应/退出/无效消息，现有首次取文超时 1800 ms、监视心跳 900 ms，超时必须回收进程；Core 可继续操作，下一次取文可恢复，没有模型调用被重发          |
| W0-03 | 窗口与 DPI   | 双显示器、混合缩放、负坐标、屏幕边缘、移除显示器；捕获与卡片定位正确且不丢原选区，无屏外不可找回窗口                                                  |
| W0-04 | OMP provider | 同一非敏感请求验证流式/非流式、UTF-8 分片、终态、取消、401/429、部分输出断线；真实至少两个已选 provider 接入路径，不只固定响应                        |
| W0-05 | OMP 集成 ADR | 验证 API Key/OAuth；锁定 Bun、OMP、Windows native addon、SDK wrapper/IPC、AuthStorage 注入/刷新写回、会话/压缩计量和并发钩子；核心项不可行时不关闭 W0 |
| W0-06 | OCR ADR      | 用统一数据比较候选，选定模型、runtime、语言、预后处理、许可证和安装方式；达到 OCR 文件中的基线目标或明确修订并评审支持范围                            |
| W0-07 | 资源与依赖   | 记录全进程资源和包体；确认 WebView2 缺失/已有与 OCR 完整离线资源路径，锁定工具链、版本和阈值                                                          |

W0 还必须证明模型预热/目录刷新和 cache warming、标题、memory/auto-learn、advisor 等后台行为均受控；免 Key 操作不启动 OMP，不存在隐式模型请求。Windows 分发测试要包括 native addon 加载，不能只验证 Bun 可执行。

正式 Tauri 集成、Rust/OMP IPC、DPAPI 加载、持久化账本、有界业务队列、双并发准入与 DeepSeek 流式/取消/压缩已有代码及回归证据，统一见 [验收状态](acceptance.md)。UIA 已在记事本、独立 VS Code 和 Discord 验证；浏览器未通过。真实 OAuth、第二 provider、多屏 DPI、OCR 与资源/分发必需项仍待验证，W0 不能关闭。

## W1：独立翻译闭环

| 编号  | 必需验证        | 通过标准与证据                                                                                                                        |
| ----- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| W1-01 | 干净机安装      | 无预装 Bun/Rust/OMP/扩展/Vencord 的 Windows 11 x64 可安装启动，随包 OMP/Bun 版本正确；WebView2 缺失时正确引导或安装，联网需求如实说明 |
| W1-02 | 输入/剪贴板翻译 | 保存目标语言与引擎后，输入和主动复制翻译均成功；没有持续剪贴板监听，空文本不请求                                                      |
| W1-03 | 账户与默认值    | 新增/编辑/删除、端点绑定、翻译/Ask 默认分离；保存后退出重启仍一致，配置失败不会显示伪成功                                             |
| W1-04 | 免 Key 独立     | 没有/错误模型账户时仍可选免 Key 引擎；添加账户不覆盖引擎，服务失败不跨 provider 或自动付费降级                                        |
| W1-05 | 任务一致性      | 快速连发、编辑原文、关闭卡片、取消、手动重试、切换引擎；旧响应不覆盖新任务，同一调用用量不重复                                        |
| W1-06 | 卡片与托盘      | 可复制、Esc 关闭、重新打开、暂停快捷键/改键、冲突反馈；单实例，无悬空窗口或失效快捷键                                                 |
| W1-07 | 故障与安全      | 断网、超时、限流、错误密钥、恶意模型 HTML/链接、越权 IPC；提示清楚，无脚本执行/凭证泄露/自动重放                                      |

通过一条真实“输入或复制 → 翻译 → 展示 → 复制结果”流程后才算闭环；构建成功或静态卡片截图不足以通过。

| W2-04 | OCR 质量       | 在冻结验收集执行完整 CER/检测/顺序/性能检查；记录每类错误与限制，模型 hash 和版本与分发一致                            |
| W2-05 | 固定阅读       | 原文/译文上下或并排、拖动/缩放、多固定窗、屏幕切换；固定内容不被后续截图改写                                           |
| W2-06 | 本地识别边界   | 断网且资源已安装仍可 OCR，抓取请求证据证明默认不上传图像；仅识别不调用翻译服务                                         |
| W2-07 | 稳定性         | 200 次取文/识别/关闭循环和至少 50 次取消/worker 故障；无 Core 卡死、句柄持续增长或进程残留                             |

## W3：模型能力、Ask、计量与迁移

| 编号  | 必需验证       | 通过标准与证据                                                                                                                                                                           |
| ----- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| W3-01 | 首版接入矩阵   | 对模型方案中的必需项逐项验证真实成功和失败；未验 provider 不出现在支持列表，模型目录与实际权限分开                                                                                       |
| W3-02 | OAuth 生命周期 | 新登录、取消、回调冲突/超时、过期刷新、刷新轮换、退出、失效、账号切换与重启；官方订阅 token 不进入自定义端点                                                                             |
| W3-03 | Ask 隔离       | 围绕固定快照追问/停止/新建，多个窗/会话/账户不串内容；关闭清理；不读文件、不调用工具、不读取原应用额外内容                                                                               |
| W3-04 | 容量与压缩     | 小容量固定模型与真实模型均验证前置检查；摘要独立计量，失败保留旧上下文；只有一个上下文权威，无双重压缩                                                                                   |
| W3-05 | 用量口径       | 固定数据覆盖缓存/reasoning 包含关系、无 usage、部分失败、取消、价格缺失、重复终态、并发与压缩；明细/汇总可对账，unknown 不记零                                                           |
| W3-06 | 迁移           | 有/无旧配置、重复导入、损坏 schema、中断和回滚；新数据事务提交，默认值引用一致，旧数据保留，收据幂等                                                                                     |
| W3-07 | 持久化/清除    | 重启恢复设置/账户/术语；内容历史默认无落盘；用量历史开关/清除与异常退出恢复符合设计；DPAPI 失败不当作无账户                                                                              |
| W3-08 | OMP 隔离与策略 | 多个顶层会话使用私有 AgentRegistry/隔离 Settings；空工具、无 MCP/LSP/扩展发现；不读取全局 .omp/.env；禁用自动轮换/回退/一般付费重试；非终态 agent_end 不当成功；销毁和 worker 重启有证据 |

OMP 是首版必需组件，W3-08 不得标为不适用；工具/资源禁用、会话压缩、凭证刷新、账户固定、真正终态和用量必须实际验收。真实登录必须用户在供应商页面完成；缺少授权无法完成的项保持环境受限。

首次桌面版没有上一桌面正式版时，W4-02 用同一 schema 系列的两个测试安装版本演练并标明模拟升级，不能称为已经验证真实跨发行升级。存在数据 schema 降级限制时禁止旧版本直接打开新版数据库，需使用匹配备份恢复。

## 性能与稳定性初始目标

以下均为待验证目标。W0 固定参考机（建议 Windows 11 x64、4 核以上 CPU、16 GB RAM、SSD）、电源模式、显示器与测试工具；资源范围包含 Core、WebView2、UIA、OCR 和 OMP/Bun 全部进程。报告进程树 private bytes、working set、CPU 核心归一化口径，不能把各进程 RSS 简单相加当作独占内存。

| 场景           | 测量与初始门槛                                                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 快捷键本地反馈 | 热状态至少 100 次，本地可见反馈 p95 ≤100ms；不含取文/OCR/模型等待                                                                         |
| 取文截止       | 正常/阻塞/超时各 30 次，约 1 秒失败返回；异常后下一次可恢复，不卡 Core                                                                    |
| OCR            | 按 OCR 文档区域/行数约束，冷/热各至少 30 次，热 p95 ≤1.5 秒、冷 p95 ≤3 秒                                                                 |
| 启动           | 机器重启后首次与进程冷启动分开；进程冷启动 30 次，托盘可操作 p95 ≤2 秒                                                                    |
| 托盘空闲       | 无窗、无任务、OCR 已卸载后连续 10 分钟，平均消耗≤0.5% 单个逻辑核容量，无周期性屏幕/网络采集                                               |
| 内存           | 初始目标：托盘稳定后总 private bytes ≤150 MiB，普通卡片无 OCR 时≤250 MiB，OCR 峰值≤700 MiB；W0 用完整原型验证，未通过需定位或重新评审预算 |
| 稳定性/增长    | 2 小时混合操作，至少 200 次流程；相同空闲点最终 private bytes 增量≤20 MiB，句柄/子进程无持续增长；解释缓存与噪声，不只看一次峰值          |
| 分发体积       | W0 分列应用本体、OCR/runtime/字典、WebView2 和 OMP/Bun；比较首次联网流量与完整离线包，不从小型 bootstrapper 大小推断总体积                |

模型延迟独立报告首正文延迟、总耗时、有效 TPS 与供应商/model/网络环境；不将供应商网络慢直接归为 UI 卡顿，也不把模拟模型延迟当成真实性能。

## 测试与发布门禁

纯领域/迁移用固定数据与故障注入；OMP 会话、压缩和凭证边界需要 SDK 集成测试；provider 协议用脱敏录制/合成事件；真实外部调用验证服务/认证；原生窗口和取文/OCR 用已安装应用实测。Rust 引入后总检查入口包含格式、Clippy、Rust 单元/集成测试、Windows 构建和受影响前端检查；共享旧包有变更时也检查旧消费者。

每个阶段输出一份验收记录和问题列表，引用上述编号；必须填写实际结果与证据，不能复制本计划的“通过标准”作为结果。纯文档阶段只做格式、链接和引用核对，不运行原型或供应商测试，不把文档通过等同于 W0 通过。
