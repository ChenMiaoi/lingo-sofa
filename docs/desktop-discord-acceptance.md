# Discord 修复与交付验收

2026-10-21，Windows 本机。Discord 1.0.9262 的 LLVM / #llvm 现有消息正文用于真实跨应用验收；操作只包含选区、全局快捷键、滚动和桌面 LingoSofa。**没有发送任何 Discord 消息**，没有向消息输入框输入样文，没有回复、转发或添加反应。原有 Vencord 插件按钮未用于这次测试。

## 发现与修复

焦点落在 Discord 消息控件时，直接获取 TextPattern 失败，原实现错误提示“不支持选区”。修复后先验证焦点到来源窗口的祖先路径，再向上查找提供 TextPattern 的控件。只允许该路径，最多 32 层；不搜索兄弟、不扫描文档后代，不读取 DocumentRange。路径中的密码控件、属性读取失败、来源不匹配和循环均拒绝；返回选区前再次核对前台窗口。

新增三项回归覆盖：文档祖先可达但不越过来源窗口、外部/循环焦点有界拒绝、密码或不可读祖先禁止向文档回退。原有首帧/心跳超时、帧大小、选区长度及 Windows Job 回收保留。

## 真实场景结果

| 场景               | 结果                                                                                                                   |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 修复前选区翻译     | 失败：“此应用暂不支持读取选区，可复制后翻译。”                                                                         |
| 修复后同一选区     | 通过：`it should probably be more explicit that you shouldn't wait for assignment` 对应译文正常显示                    |
| 消息列表滚动       | 通过：向上滚动使原文实际移动，译文收起；在滚动边界没有移动的尝试不算通过依据                                           |
| Ask 来源           | 通过：展开后只含选中句子，来源提示为 Discord，原文共 75 字符（含提供方附带的空白），不含邻近消息或作者信息             |
| Ask 回答           | 通过：只在桌面 Ask 输入“根据当前所选原句，是否应该等待 assignment？只返回‘应该等待’或‘不应该等待’。”，回答“不应该等待” |
| 再次滚动           | 通过：Ask 保留冻结原文和回答，不恢复成其他消息                                                                         |
| Discord 消息输入框 | 始终为空；所有 Enter 均发送给桌面 LingoSofa，而非 Discord                                                              |

此次有 3 次真实 DeepSeek generation（两次翻译、一次 Ask），共 493 tokens，均为 reported，未知与 pending 为 0。使用被 Git 忽略的隔离 DPAPI profile，不配置日常桌面账户。见 [用量证据](validation/discord/usage-summary.json)。没有为本轮文档和统一输入面板再发起付费模型请求。

## 输入复用 Ask

输入翻译现在使用 Ask 的深色面板、动作列表和结果区域，多行文本支持 Shift+Enter 换行，Enter 执行，Alt+↑↓ 选择翻译或新问题。只有显式执行才提交。翻译在新会话运行；“作为新问题提问”同样强制新建模型会话，避免继承旧阅读内容或翻译指令。结果支持同面板继续追问、取消、复制和压缩。

挂载真实 React 组件的回归覆盖空白/忙碌禁用、输入法确认、换行保护、动作选择、无自动请求及新入口命令。服务集成回归会检查实际模拟供应商收到的消息，确认独立新问题不含旧阅读标记。

原生统一输入面板使用独立无账户目录检查：空文本时动作禁用、多行输入、Shift+Enter 换行、Alt+↑↓ 切换动作、Enter 后在同一结果面板显示账户错误均通过。该目录用量账本为 0 条模型调用。真实中文输入法和新输入功能的付费端到端调用未在本轮重测；对应事件和供应商消息隔离由上述回归验证。
