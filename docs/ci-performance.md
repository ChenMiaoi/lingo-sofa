# CI 耗时与优化验证

CI 保留 Windows x64、macOS 26 arm64 和 macOS 26 Intel 的全部检查。未删除测试、过滤慢测试或增加失败重试。

## 测试计时与有限并行

运行时测试使用固定版本 cargo-nextest 0.9.149，默认最多并行 2 项，每项测试运行在独立进程。临时目录、数据库、fixture 服务和 worker 均由对应测试独立创建；现有测试没有修改全局环境变量。源码 worker 与独立编译 worker 仍各运行完整测试集合。Nextest 不运行 rustdoc 测试，因此脚本另行执行原来的 Cargo 文档测试。

`.cache/runtime-tests/source.json` 和 `packaged.json` 包含每项测试的套件、名称、通过状态、耗时，以及 worker 准备、编译、执行和文档测试阶段的耗时；同时输出最慢 10 项测试、JUnit XML 和 Cargo 编译时间图。报告缺失、数量不符、重复结果、测试失败、非零退出或关键崩溃恢复测试没有执行，均不能显示通过。失败重跑次数为 0。

可用 `LINGOSOFA_TEST_THREADS=1` 取得串行基线，设置为 `2` 或不设置则使用有限并行。其他值会拒绝执行。360 秒执行期限从测试编译完成后开始计算。

本机 macOS 27.0.1 arm64 的暖缓存对照结果：

| 模式            | 串行测试执行 | 2 项并行测试执行 |  减少 |  测试数 |
| --------------- | -----------: | ---------------: | ----: | ------: |
| 源码 worker     |    38.818 秒 |        21.246 秒 | 45.3% | 47 → 47 |
| 独立编译 worker |    41.154 秒 |        22.071 秒 | 46.4% | 47 → 47 |

每组为一次测量，四组顺序执行，避免互相争用资源。逐项测试名称与优化前 Cargo 报告一致，四组全部通过。对照双方使用同一个 Nextest 版本，表中的变化只比较并发设置；不能直接推算 Windows、Intel 或整条 CI 的收益。完整数据、慢测试和输入哈希见 [验证报告](validation/ci-performance.json)。

## 复用构建产物

`npm run check` 仍是本机完整验证入口。CI 将其相同检查拆成单独步骤，使 GitHub 能直接显示各阶段耗时，顺序仍确保先准备资源再构建桌面程序。

CI 最后使用 `npm run bundle -- --debug`，直接调用 Tauri 的独立打包命令，复用已经检查并生成的桌面二进制、前端、worker、选区 helper 和原生 addon，不重复运行 worker 编译、Vite 或 Cargo 构建。打包前逐项检查输入文件和所选 debug/release 目录，缺失时明确失败。本机已验证独立打包生成 `.app`、`.dmg`，并通过隔离数据目录的启动检查；打包前后前端入口和 runtime 资源哈希一致。普通 `npm run build` 和 `npm run dev` 的完整准备流程保持原样。修改源码后应重新构建或执行完整检查，再使用独立打包命令。

## 缓存观察

Rust 缓存按 runner 标签区分，保留 action 默认的依赖缓存策略。它缓存 Cargo 依赖和 target 下的依赖产物，不缓存工作区 crate；没有为缩短 CI 而关闭 lint、测试或编译。`cache-bin: false` 避免从缓存恢复工具程序，Nextest 单独安装固定版本的预编译程序。

每次 CI 在摘要中记录 Rust 缓存是否精确匹配，并上传 Cargo 编译时间图和运行时分阶段数据。精确匹配为 false 时仍可能恢复了前缀匹配的部分缓存，需要结合 action 的恢复日志判断。首次构建和依赖变动仍可能较慢。

本机两项并行测量的测试编译阶段命令约 0.4～0.5 秒，属于已经预热的本机缓存；尚无新版远端 CI 的缓存命中对照，不把本机结果作为远端缓存收益。
