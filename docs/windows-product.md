# LingoSofa：Windows 独立悬浮翻译产品规划

日期：2026-10-21。状态：产品方向已确认，基础桌面已进入正式实现，完整功能尚未验收。选型建议和验证门槛见 [技术方案](lingo-sofa-plan.md)。

## 产品定位

LingoSofa 是随时翻译正在看的内容、并围绕它继续理解的桌面软件。首个目标为 Windows 11 x64：安装一次，在浏览器、Discord、PDF 阅读器或编辑器中使用统一快捷键和翻译窗口，无需先安装浏览器扩展或修改 Discord。

主体验从适配每个宿主并插入译文，转向用户主动取文、在独立卡片或阅读窗中查看双语内容。跨应用是首版目标，跨操作系统是后续方向；不将所有应用、Windows 版本和处理器架构统称为已支持。

选型以新产品的常驻体验、系统能力与长期维护为依据，既有投入和重写工作量不参与取舍。技术基线确定为 Tauri 2 + Rust 桌面核心 + React/TypeScript 界面，oh-my-pi SDK/Agent 统一承担 LLM provider、认证、翻译/Ask 会话与压缩。应用携带所需 Bun/OMP，用户不另装助手；Rust 不重复实现一套 LLM 会话层。模型、账户与 Ask 能力仍需逐项验收。

## 解决的问题

- 翻译入口与设置分散，用户需要理解扩展、插件和本地助手的连接关系。
- 图片、扫描 PDF 和无法选中的界面文字缺少统一入口。
- 译文与问答依附宿主，切换软件后操作不同，维护受宿主更新影响。

产品统一账户、模型、术语与用量配置。保留原文、默认忠实翻译，解释、总结和润色由用户主动发起。

## 首版流程

| 场景              | 动作                         | 结果与失败处理                                    |
| ----------------- | ---------------------------- | ------------------------------------------------- |
| 可选中的词句/段落 | 选中文字，按翻译快捷键       | 原文/译文卡片；无法取文时提示复制后翻译或框选识别 |
| 图片或不可选段落  | 框选快捷键，选中目标区域     | 本地 OCR 后翻译，可修正识别原文；Esc 退出         |
| 已复制的内容      | 主动复制，按剪贴板翻译快捷键 | 仅读取当次文本，不常驻监听                        |
| 自己需要写外语    | 打开输入翻译，输入或粘贴     | 选择方向、翻译、复制，不自动粘贴或发送            |
| 需要持续阅读      | 固定当前卡片                 | 可移动、缩放的双语阅读窗，保留内容快照            |
| 译文仍难理解      | 在卡片中继续提问             | 围绕明确展示的原文/译文问答，支持停止与新建       |

输入、选区和剪贴板默认分别使用 Alt+Shift+Space、Alt+Shift+S、Alt+Shift+T，可在设置中改键并查看启用状态；暂停入口仍是后续目标。首次设置选择目标语言和引擎；保留免 Key 翻译与自有模型，Ask 单独配置。服务失败不自动切换供应商或付费模型。

首次启用取文/截图时说明范围与数据去向；设置完成后，翻译快捷键即代表发送本次内容，不每次重复确认。仅识别不发送给翻译服务；框选翻译默认只发送识别文本，不上传图像。

## 窗口与交互

- **托盘**：常驻入口，提供输入翻译、设置、暂停快捷键和退出；开机启动可选、默认关闭。
- **临时卡片**：按需显示原文和译文，提供复制、重试、固定与提问。加载/失败/取消状态清晰，Esc 关闭；不默认放长期遮挡内容的悬浮球。
- **固定阅读窗**：可拖动、缩放，原文/译文上下或并排。保留当前快照，不默默跟踪来源应用或追加内容。
- **设置窗**：集中管理翻译、Ask、账户、快捷键、术语、用量和隐私，延续现有品牌，去除桌面不需要的宿主连接步骤。

取文先于窗口激活；读文卡片默认不抢焦点，点击后才交互。功能提供键盘路径，支持深浅主题和高 DPI。费用与速度置于可展开区域，不挤占译文主体。

## 范围与限制

首版包括选区快捷键翻译、主动剪贴板翻译、输入翻译、框选本地 OCR、固定阅读、上下文 Ask、统一账户、术语和已有用量展示。真实可用性依赖目标应用的取文和截图支持，必须发布已测覆盖表。

首版不包括全屏持续 OCR、鼠标划过即翻译、自动监听所有复制内容、跟随滚动的逐段覆盖层、任意软件原位插入译文、整篇 PDF 导入与排版还原、字幕/音视频、移动端，以及 macOS/Linux 同步交付。

识别段落是框选范围内的文本识别和块整理，固定阅读是已取得内容的阅读；均不意味着获取未显示的长文或自动处理整页。长文连续阅读与文档导入在首版验证后另行设计。

## 数据与控制权

- 只在用户操作时取文，不后台扫描窗口或持续采集屏幕。
- 本地 OCR，截图默认不落盘；原文、译文和 Ask 正文默认只存内存。用量历史仅保存统计元数据。
- 翻译/Ask 将明确范围的文本发送到所选服务；不因本地识别宣称翻译完全离线。
- 固定窗属于当前会话，退出后默认不恢复正文；未来内容历史需独立设置与清除入口。
- 凭证经 Windows 用户绑定的加密存储保存，不进入卡片、日志或统计。
- 失败/取消可能已产生费用，保留已有用量和未知状态，不自动重放请求，不新增本地预算限制。

## 现有用户与交付

浏览器和 Discord 集成保留为现有版本能力，本次不删除代码、不卸载组件、不修改用户设置。新功能优先投入独立桌面版，旧集成是否长期保留依桌面版反馈另行决定。

桌面版使用独立安装身份和更新通道，不能把现有 Discord 安装器改名当作独立翻译软件。安装包携带匹配的 Bun/OMP，安装后不要求用户另装 Bun、Rust、OMP、Vencord 或扩展；OCR 语言资源、联网需求和签名状态需明示。旧账户通过主动导入迁移，先备份、原子提交并保留旧数据。

## 成功标准与顺序

1. 验证真实取文、截图 OCR、多屏定位、模型后台运行和资源消耗。
2. 交付独立翻译闭环，完善取文/OCR、固定阅读、Ask 和迁移。
3. 完成干净机安装、升级、退出和故障恢复验收，形成下载候选版本。

核心验收是无需扩展/插件，在真实应用完成选取或框选 → 翻译 → 固定 → 继续提问，失败时有可用的降级方式。至少覆盖 Chrome/Edge、Discord、一个文本 PDF 和一个扫描 PDF、一个编辑器；记录应用版本、取文支持与 OCR 结果，不把一次成功推广为全应用支持。

多屏混合缩放、快捷键冲突、丢焦点、空选区、中英文混排、OCR 错误、断网、429、取消、进程崩溃、锁屏和升级恢复纳入验收。冷启动、空闲内存/CPU、取文/OCR 耗时按同一机器记录，模型延迟单列。W0–W4 门槛见 [技术方案](lingo-sofa-plan.md)。
